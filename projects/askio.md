# Askio · 运维排障 AI 助手

> 用调查图组织排障方向，让 Agent 围绕证据推进调查，并复用历史排障经验。

- 项目背景：上海七牛信息技术有限公司产品架构部实习项目
- 实习时间：2026 年 5 月至 9 月
- 我的角色：五人小组组长；主导整体架构、技术选型和 Agent 核心实现
- 项目入口：[Askio 官网](https://www.askio.site/)

## 背景与目标

运维排障往往同时涉及指标、日志和 Trace。长对话中的多种猜测不易追踪，证据分散在不同数据源，完成后的排障过程也难以复用。Askio 以调查图呈现排查方向，由 Agent 调用工具取证，同时让用户能够介入和纠偏。

## 我负责的工作

- **调查图与 Agent：**将一次排障组织为“根节点 → 排查节点 → 故障域”，支持分叉、汇聚与排除方向。Agent 在图上拆解问题、调用数据源工具；信息不足时继续提问，用户可以打断调查并修正方向。
- **经验沉淀与检索：**将已完成的调查结构化为“故障现象 → 故障域 → 排障思路”。后续调查通过 RAG 召回相似经验，选择可复用的排障链路，再以当前数据重新验证。
- **整体架构与技术选型：**以调查图实体变更、消息增量、工具调用和审批等事件协调模块，通过 SSE 向前端推送进展。基于 NestJS、Fastify、ts-rest 与 Zod 组织 HTTP / SSE 接口合同，使用 PostgreSQL / pgvector、BullMQ / Redis 支撑存储与异步任务。

## 一次调查如何推进

1. 用户描述现象，系统创建调查图根节点。
2. Agent 拆解可能的方向，建立可并行推进的排查节点。
3. 各分支查询指标、日志与 Trace；证据支持的方向逐步汇聚，无效方向被排除。
4. 用户确认根因后，将调查过程沉淀为结构化经验，供后续相似问题检索和验证。
